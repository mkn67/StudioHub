## Môi trường và kết quả thực tế

- Frontend production Next.js 16.4.3; NEXT_PUBLIC_API_URL=http://localhost:8000. Không đổi .env thật.
- Get-Command php,mysql: không có executable trên PATH. Docker CLI có nhưng daemon pipe docker_engine không tồn tại.
- Fetch thật GET http://127.0.0.1:8000/api/health và GET /api/rooms: **ECONNREFUSED**, không nhận HTTP status/body. Không đủ cơ sở kết luận controller/DB hỏng.
- Không có server/.env; Compose truyền cấu hình DB từ môi trường. Chỉ liệt kê tên khóa cấu hình, không xuất bí mật.
- Không chạy login thật, API ghi, migration, seed, SQL, Docker up/down/restart, PHP test hoặc AI trả phí. Không ghi dữ liệu production.
- **0 VERIFIED_HTTP; 0 VERIFIED_DATABASE_PERSISTENCE.** Tất cả 80 API ở trạng thái runtime chưa kiểm chứng; chỉ 79 thao tác có quan sát browser fixture trong lượt này.

## Kiểm thử browser bằng fixture

Lệnh: `node scripts/rest-integration-qa.mjs` từ client. Tất cả request API được Playwright chặn và trả fixture, mọi origin ngoài server QA bị chặn; không request nào tới PHP/MySQL. Dữ liệu thay đổi trong bộ nhớ fixture được đọc lại khi reload, chỉ chứng minh revalidation của frontend. Không phải bằng chứng persistence DB. Summary máy đọc: client/test-results/rest-integration/summary.json.

Các kiểm tra đã hoàn tất:

- Host: tổng quan, sửa Studio/cover, sửa loại phòng, upload ảnh phòng/thiết bị, tạo nhóm/thiết bị, tạo/sửa giá.
- Xác thực: đăng nhập và điều hướng Customer/Host/Admin, tải profile đầy đủ, đăng ký/đăng xuất; Admin sửa Studio/phòng, gửi yêu cầu khóa và đổi role.
- Guest/booking: chi tiết phòng/tiện ích/lịch công khai, quote/tạo đơn/chi tiết/cọc sandbox/hủy; Host nhận phòng/hoàn tất. Số tiền là fixture phản hồi API, không kiểm chứng tính toán PHP.
- Customer: hồ sơ, email hai bước, avatar, tùy chọn thông báo, xác minh và đăng ký Host; GET lại fixture sau reload.
- Host: phòng ẩn/thiết bị inactive, loại phòng, sửa tài nguyên, DELETE bị từ chối rồi thành công, lịch, chính sách, pháp lý và PDF dùng JWT.
- Admin: chi tiết/quyết định hồ sơ, sửa thiết bị, role catalog, đối soát thủ công có chứng từ, audit và báo cáo cùng bộ lọc ngày.
- Lỗi 500/contract không bị hiển thị thành rỗng; chặn sai role, hết phiên; 5 viewport; không tải workspace rộng trong luồng REST.

## Chuẩn bị DB test — hướng dẫn cho người phụ trách backend

Các lệnh dưới đây **chưa được chạy** trong lượt này. Chỉ dùng bản sao DB phát triển riêng, tuyệt đối không dùng --fresh hoặc bootstrap/seed trên DB hiện hữu.

1. Xác nhận PHP >=8.2, pdo_mysql, fileinfo, Composer vendor; tạo DB test độc lập. Cấu hình APP_ENV=test, DB_NAME=studio_backend_test cùng DB_HOST/PORT/USER/PASS của DB test. Không tái dùng credentials production.
2. Kiểm tra read-only: SHOW COLUMNS FROM schema_migrations; SELECT DATABASE(); SHOW CREATE TABLE bookings; đối chiếu migration tracker trước khi chạy script.
3. Tracker SQL dùng cột migration (database/migrate-up.php), tracker PHP dùng version (bin/migrate.php). Không chạy cả hai mù quáng trên cùng tracker vì CREATE TABLE IF NOT EXISTS không thêm cột còn thiếu. Cần backend thống nhất runner trước.
4. Sau khi xác nhận tracker SQL và các migration đã ghi nhận đúng: từ server chạy `php database/migrate-up.php` trên **DB test** để áp dụng migration SQL còn thiếu. Đây có DDL, chỉ chủ DB test thực hiện sau review. Không tự dùng bin/migrate.php --apply vì nó thay lifecycle booking và không tương thích hoàn toàn luồng REST.
5. Các phần cần kiểm tra: 009 host_applications; 010 users.date_of_birth/address; 011 email_change_requests/account_notification_preferences/identity_verifications/studio_policies/studios.cover_url/equipment_images/bookings.policy_snapshot; 012 host_room_types/rooms.room_type_id/host_legal_profiles/host_contracts/contract_document_access_grants/refund_exception_actions. Đối chiếu information_schema.columns/tables với đúng DB test; chưa kết luận DB hiện tại thiếu chúng.
6. Kiểm tra quyền ghi public/uploads và private-identities/private-contracts; cấu hình mail production riêng; APP_ENV=test dùng development_code nên không xác nhận gửi email thật.
7. Sau khi schema/lifecycle được backend xác nhận: chạy unit PHP, test Integration trên DB test và HTTP workflow bằng tài khoản test. Đối với mutation, ghi ID rồi GET lại/refresh browser và truy vấn DB test để xác nhận persistence; kiểm tra role/owner, 409 DELETE và đối soát thủ công. Không gọi AI trả phí.
